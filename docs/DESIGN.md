# 英语森林 English Forest

## 产品设计文档 DESIGN V0.1

## 1. 设计目标

第一版不是做"漂亮的电子教材"，而是做一个让小学生可以独立完成一次学习闭环的互动产品。

核心体验：

``` text
看到知识
  ↓
理解规则
  ↓
马上练
  ↓
答对有反馈
  ↓
答错有提示
  ↓
看到自己的掌握情况
```

## 2. 视觉方向

关键词：

-   森林
-   探险
-   轻游戏
-   明亮
-   儿童友好
-   清晰
-   少文字
-   大点击区域

不追求复杂 3D。

第一版用 2D 卡片、树木、角色、星星、进度条和简单动画建立游戏感。

## 3. 页面结构

### 3.1 首页

核心目标：

> 告诉孩子"今天做什么"。

结构：

``` text
顶部
┌──────────────────────┐
│ 🌳 英语森林     Lv.1 │
│ XP ███████░░░         │
└──────────────────────┘

今日挑战
┌──────────────────────┐
│ 🐉 比较级大冒险       │
│ 动态题量             │
│ ⭐⭐⭐                │
│                      │
│ [ 开始挑战 ]          │
└──────────────────────┘

我的学习
┌────────┐ ┌────────┐
│ 🌿 语法 │ │ 🌱 错题 │
└────────┘ └────────┘
```

首页不放复杂导航。

## 4. 知识点页面

目标：

> 在做题之前快速理解知识。

### 页面结构

``` text
← 返回

🐉 比较级和最高级

普通变化
┌──────────────────────┐
│ long                 │
│ longer               │
│ longest              │
│                      │
│ 一般直接加 er / est   │
└──────────────────────┘

y 结尾
┌──────────────────────┐
│ busy                 │
│ busier               │
│ busiest              │
│                      │
│ y → i + er / est      │
└──────────────────────┘

[ 开始挑战 ]
```

每个知识规则都是独立卡片。

## 5. 学习页

学习页与知识点页可以在 MVP 中合并。

如果后续内容变多，再拆成：

-   知识概览
-   深入学习

### 交互

点击单词：

-   播放发音
-   显示中文
-   显示例句

第一版音频可以使用浏览器 SpeechSynthesis
API，不要求提前准备大量音频文件。

## 6. 闯关页

这是整个 MVP 的核心页面。

### 顶部

``` text
←     3 / 10      ⭐ 20
```

### 中间

题目卡片。

### 底部

答案区域。

例如：

``` text
┌──────────────────────┐
│                      │
│  busy 的比较级是？    │
│                      │
└──────────────────────┘

┌──────────────────────┐
│       busyer         │
└──────────────────────┘

┌──────────────────────┐
│       busier         │
└──────────────────────┘

┌──────────────────────┐
│       busiest        │
└──────────────────────┘
```

## 7. 答题状态

每道题至少有四种视觉状态：

``` text
未作答
  ↓
已选择
  ↓
正确 / 错误
  ↓
进入下一题
```

不要让用户在选择答案后还需要额外点击复杂的"提交"按钮。

选择后即可判断。

## 8. 正确反馈

例如：

``` text
🎉 Great!

busy → busier

+10 XP
```

短暂展示后进入下一题。

## 9. 错误反馈

错误时：

``` text
再想一想！

❌ busyer

✅ busier

规则：
y → i + er
```

错误反馈应该帮助理解，而不是制造失败感。

## 10. 结果页

``` text
🎉 挑战完成！

       ⭐⭐⭐

正确率
80%

+100 XP

知识点：

普通变化      🌳
e结尾         🌳
y → ier       🌿
双写          🌳
不规则        🌱

[ 再练一次 ]

[ 返回英语森林 ]
```

如果存在明显薄弱知识点，可以突出：

> "再练 3 道不规则变化"

## 11. 错题状态

错题不要单独做成复杂页面。

MVP 可以先在结果页提供：

``` text
本次需要复习

🌱 good → better
🌱 many → more
```

后续再建立独立"错题森林"。

## 12. 数据与 UI 的关系

UI 不直接保存教材内容。

推荐数据流：

``` text
CONTENT DATA
     ↓
KnowledgePoint
     ↓
Question
     ↓
GameSession
     ↓
Attempt
     ↓
KnowledgeMastery
```

页面只负责展示和交互。

内容结构定义见 `CONTENT.md`。

技术状态和持久化定义见 `TECH.md`。

## 13. 移动端

移动端优先。

设计原则：

-   主要按钮宽度足够大
-   避免小图标作为唯一操作入口
-   单手操作尽量可完成
-   题目和答案保持明显层级
-   避免一次出现过多内容

## 14. 动画

MVP 只需要轻量动画：

-   XP 增加
-   星星出现
-   答对反馈
-   答错反馈
-   页面切换

暂时不做：

-   3D
-   粒子系统
-   复杂角色动作
-   地图实时探索

## 15. 音效

后续可以增加：

-   正确音效
-   错误提示音
-   升级音效
-   完成挑战音效

第一版可以不依赖音效资源。

## 16. 设计原则

### 原则一

孩子不需要阅读长篇说明才能开始。

### 原则二

每一屏只有一个最主要动作。

### 原则三

错误后马上解释。

### 原则四

游戏反馈必须服务学习。

### 原则五

所有内容组件都应该可以复用。

例如：

``` text
QuestionCard
AnswerButton
KnowledgeCard
ProgressBar
XPBar
ResultCard
```

不要为每一道题单独写页面。

## 17. 后续扩展

未来增加拍照导入后：

``` text
📷 拍照
 ↓
AI识别
 ↓
内容确认
 ↓
生成知识卡片
 ↓
生成题目
 ↓
进入同一套 Game UI
```

因此"拍照资料"和"人工录入资料"最终应该进入同一套内容模型，而不是发展成两套系统。
